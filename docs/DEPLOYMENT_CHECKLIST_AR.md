# قائمة تجهيز ممنون قبل الإطلاق — المستودع mamnoonChatGPT

هذه القائمة تخص المستودع `ali8102000/mamnoonChatGPT` والفرع `main`. لا تفترض أن أي إعداد قديم تابع لمشروع كفو أو لمشروع Supabase آخر صالح لممنون.

## 1. ربط Supabase — يحتاج تأكيداً من لوحة المشروع

توجد حالياً قيمتان مختلفتان في ملفات المستودع:
- `supabase/config.toml` يشير إلى `hvfiwjryffjwaynkpgar`.
- `config/public-backend.json` يشير إلى `tojqupbkqsnouhgioygq` ويحتوي مفتاحاً عاماً مرتبطاً بذلك العنوان.

هذا تعارض فعلي، ولا يجوز توحيدهما بتخمين أو نسخ مفتاح المشروع الأول إلى عنوان المشروع الثاني. قبل النشر، افتح Supabase Dashboard وتأكد من مرجع المشروع الذي يحتوي بيانات المستخدمين والجداول ووظائف الإنتاج، ثم اجعل إعدادات الويب والهاتف وCLI تشير كلها إلى المشروع نفسه. لا تنشر migrations أو تغيّر إعدادات Auth قبل هذا التحقق.

لا تضع كلمة مرور أو `service_role` أو أي سر في GitHub أو داخل تطبيق الهاتف.

## 2. تطبيق Android وExpo EAS

هوية تطبيق الهاتف المعتمدة في ملفات البناء:
- اسم التطبيق: ممنون.
- Expo slug: `mamnoon`.
- Android package: `com.mamnoon.app`.
- EAS project ID: `a6c763c4-3a5c-4725-b370-81967e3c0aab`.

ملف `expo-app/app.json` هو إعداد التطبيق، وملف `expo-app/eas.json` هو إعداد ملفات البناء. ملف `eas.json` في جذر المستودع نسخة توافقية ويجب إبقاؤه متطابقاً مع معرّف مشروع EAS نفسه.

تحتاج بيئة EAS المسماة `production` إلى:
- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`

يجب أن يكون رابط Supabase هو رابط المشروع الصحيح الذي تم تأكيده في الخطوة الأولى. قيّد مفتاح Google Maps باسم الحزمة `com.mamnoon.app` وبصمة شهادة التوقيع الفعلية، وفعّل واجهات الخرائط اللازمة فقط.

### إعداد GitHub لبناء AAB

من المستودع افتح `Settings → Secrets and variables → Actions` وأضف:
- Secret باسم `EXPO_TOKEN` وقيمته رمز Expo.
- لا يحتاج workflow الحالي إلى متغير GitHub منفصل باسم `EAS_PROJECT_ID`؛ معرّف EAS المثبت في workflow يجب أن يطابق `expo-app/app.json`.

يشغّل workflow فحوص TypeScript وExpo Doctor وتصدير Android، ويتحقق من تطابق معرّف EAS، ثم يبني AAB موقّعاً وينزّله ويرفعه باسم `mamnoon-production-aab` لمدة 14 يوماً. نجاح CI لا يثبت وحده عمل خدمات الإنتاج على جهاز حقيقي.

## 3. إعداد الويب والخادم

تُضبط المتغيرات في بيئة استضافة الويب والخادم، وفق أسماء الاستعمال في التطبيق:
- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` — للخادم فقط
- `GOOGLE_MAPS_API_KEY`
- `LOVABLE_API_KEY`
- `APP_URL` و`ALLOWED_REDIRECT_ORIGINS`

لا تضع `SUPABASE_SERVICE_ROLE_KEY` في المتصفح أو تطبيق الهاتف أو أي متغير يبدأ بـ `EXPO_PUBLIC_`.

## 4. وظائف Supabase — مصادرها غير محفوظة هنا

المستودع لا يحتوي حالياً على `supabase/functions/`. الوثائق والإعدادات تشير إلى وظائف مثل:
- `auth-proxy`
- `create-taxi-request`
- `subscription-cron`

لذلك لا يمكن مراجعة شيفرتها أو إعادة نشرها من هذا المستودع. يجب تصدير المصادر الفعلية من مشروع Supabase الذي تم تأكيده، وإضافتها إلى GitHub قبل اعتبار هذه الفجوة مغلقة. يجب خصوصاً مراجعة صلاحيات `auth-proxy` وملكية طلب التاكسي وجدولة `subscription-cron`. لا تنشئ بدائل تخمينية لهذه الوظائف.

## 5. قاعدة البيانات والترحيلات

ملفات SQL الحالية:
- `0000_mamnoon_tables.sql`
- `0001_mamnoon_functions.sql`
- `0002_timed_taxi_dispatch.sql`
- `0003_secure_super_admin_bootstrap.sql`
- `0004_bound_provider_map_discovery.sql`
- `0005_provider_presence_for_mobile.sql`
- `0006_secure_taxi_dispatch_retry.sql`
- `0007_sync_verified_auth_contacts.sql`
- `0008_secure_friend_workflows.sql`

سجل `drizzle/migrations/meta/_journal.json` يجب أن يتضمن كل ملف SQL بالترتيب. إضافة ترحيل إلى السجل لا تعني أنه طُبق على قاعدة الإنتاج. كما أن ملفات snapshots من `0004` إلى `0007` غير موجودة حالياً؛ لذلك لا تشغّل `drizzle-kit generate` اعتماداً على هذا السجل قبل استعادة snapshots الصحيحة أو اعتماد مسار SQL migrations موثق.

قبل أي تطبيق على الإنتاج:
1. تأكد من مرجع Supabase الصحيح.
2. خذ نسخة احتياطية قابلة للاستعادة.
3. افحص سجل `__drizzle_migrations` في قاعدة البيانات وقارنه بالملفات المحلية.
4. تحقق هل migration 0008 مطبق بالفعل أم لا.
5. اختبر على قاعدة اختبار أولاً.
6. طبّق فقط الترحيلات غير المطبقة بعد مراجعة النتائج.

أمر المشروع هو `bun run db:migrate`. لا تشغّله على الإنتاج قبل إتمام الخطوات السابقة. فحص GitHub لا يكشف حالة سجل قاعدة الإنتاج.

## 6. اختبار المسارات قبل الإطلاق

اختبر بحسابات منفصلة للزبون والسائق والفني:
- إنشاء الحساب وتأكيد البريد وتسجيل الدخول واستعادة كلمة المرور.
- اختيار الدور وتوثيق السائق أو الفني.
- منع استقبال الطلبات قبل الموافقة الإدارية.
- صلاحيات GPS عند القبول والرفض وفقدان الشبكة.
- اكتشاف مقدمي الخدمة ضمن النطاق دون كشف إحداثياتهم الدقيقة.
- إنشاء طلب تاكسي وقبوله مرة واحدة وحساب السعر من الخادم.
- بدء الرحلة وإنهاؤها وإلغاء الطلب.
- طلب خدمة منزلية وتوجيهه إلى الفني المناسب.
- المحادثة والإشعارات والتقييم.
- الاشتراكات وتجديدها وانتهاؤها.

نجاح TypeScript أو Expo Doctor أو البناء لا يعوض الاختبار الفعلي على قاعدة الإنتاج وهاتف حقيقي.

## 7. نقاط غير قابلة للإغلاق من GitHub وحده

- لا يمكن حسم مشروع Supabase الصحيح دون فحص لوحة المشروع وقاعدة بياناته.
- لا يمكن التحقق من SMTP أو وصول رسالة التسجيل أو الاستعادة إلى البريد من دون اختبار حي.
- لا يمكن مراجعة وظائف Supabase المنشورة قبل استعادة مصادرها.
- لا يمكن إثبات GPS والخرائط والإشعارات والطلبات الحقيقية دون اختبار جهاز وخدمات الإنتاج.
- لا تشارك أي token أو مفتاح خدمة في المحادثة أو داخل ملفات Git.
