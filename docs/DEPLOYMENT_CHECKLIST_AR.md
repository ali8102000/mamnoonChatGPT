# قائمة تجهيز ممنون قبل الإطلاق — المستودع mamnoonChatGPT

هذه القائمة تخص المستودع الحالي `ali8102000/mamnoonChatGPT` والفرع الأساسي `main`. لا تستخدم إعدادات أي مشروع Supabase قديم.

## 1. ربط الخدمات الصحيحة

معرّف مشروع Supabase المحدد في `supabase/config.toml` هو:

`tojqupbkqsnouhgioygq`

تأكد من أن رابط Supabase المستخدم في الويب والهاتف يعود إلى هذا المشروع. لا تضع كلمات المرور أو مفاتيح الخدمة في GitHub أو المحادثة.

## 2. إعداد تطبيق Android في Expo EAS

في لوحة Expo EAS، أنشئ/تحقق من مشروع التطبيق المرتبط بالـ slug `mamnoon`، ثم أضف في بيئة EAS المسماة `production`:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`

يجب أن يكون رابط Supabase HTTPS. مفتاح Google Maps مخصص للعميل، لذلك قيّده باسم الحزمة `com.mamnoon.app` وبصمة شهادة التوقيع الفعلية، وفعّل واجهات الخرائط المطلوبة فقط.

### إعداد GitHub لبناء AAB

من المستودع افتح:

`Settings → Secrets and variables → Actions`

- ضمن **Variables** أضف `EAS_PROJECT_ID` بقيمة UUID لمشروع Expo الفعلي.
- ضمن **Secrets** أضف `EXPO_TOKEN` بقيمة رمز Expo.

`EAS_PROJECT_ID` معرّف مشروع وليس كلمة سر. يحتاجه إعداد Expo قبل أن يتمكن EAS CLI من جلب متغيرات بيئة الإنتاج. لا تخمّن هذا المعرّف ولا تستخدم معرّف مشروع آخر.

بعد ضبط القيم، شغّل workflow المسمى **Android production AAB** من GitHub Actions. يتحقق الـ workflow من الرمز ومعرّف المشروع، ثم يتحقق من متغيرات EAS الإنتاجية قبل بناء AAB. لا يكتمل بناء المتجر إذا كانت هذه الإعدادات ناقصة.

## 3. إعداد الويب والخادم

أضف المتغيرات المناسبة إلى بيئة استضافة الويب والخادم:

- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` — للخادم فقط
- `GOOGLE_MAPS_API_KEY`
- `LOVABLE_API_KEY`
- `APP_URL` و`ALLOWED_REDIRECT_ORIGINS`

لا تضع `SUPABASE_SERVICE_ROLE_KEY` في المتصفح أو تطبيق الهاتف أو أي متغير يبدأ بـ `EXPO_PUBLIC_`.

## 4. وظائف Supabase

تأكد من نشر الوظائف التالية في مشروع Supabase الصحيح بعد مراجعة إعداداتها وأسرارها:

- `auth-proxy`
- `create-taxi-request`
- `subscription-cron`

تحتاج الوظائف إلى الأسرار الخادمية المناسبة مثل `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`. وظيفة `subscription-cron` يجب أن تستدعى بواسطة مجدول موثوق، ولا تفتحها للعامة.

## 5. قاعدة البيانات والترحيلات

سجل Drizzle الحالي في المستودع يحتوي على:

- `0000_mamnoon_tables.sql`
- `0001_mamnoon_functions.sql`
- `0002_timed_taxi_dispatch.sql`
- `0003_secure_super_admin_bootstrap.sql`
- `0004_bound_provider_map_discovery.sql`

وجود ملف migration في GitHub لا يثبت أنه طُبق على قاعدة الإنتاج. قبل أي ترحيل:

1. تحقق من أن اتصال قاعدة البيانات يعود إلى مشروع Supabase الصحيح.
2. خذ نسخة احتياطية قابلة للاستعادة.
3. قارن سجل Drizzle الفعلي في قاعدة البيانات مع `drizzle/migrations/meta/_journal.json`.
4. لا تعِد تطبيق ترحيل مطبق، ولا تتجاوز أي ترحيل مفقود.
5. اختبر التغييرات على بيئة اختبار أولاً، ثم اختبر التسجيل والأدوار والطلبات والموقع والصلاحيات.
6. طبّق على الإنتاج فقط بعد نجاح المقارنة والاختبار.

أمر الترحيل في المستودع هو `bun run db:migrate`. لا تشغّله قبل إتمام الخطوات أعلاه. لم يتم من خلال فحوص GitHub إثبات حالة قاعدة الإنتاج أو تنفيذ ترحيل عليها.

## 6. الاختبار الفعلي المطلوب

اختبر بحسابات منفصلة: زبون، سائق، وفني.

- إنشاء الحساب وتسجيل الدخول واستعادة كلمة المرور.
- اختيار الدور وإكمال بيانات السائق أو الفني.
- عدم السماح باستقبال الطلبات قبل التوثيق الإداري.
- منح إذن GPS ورفضه، وتغيير الموقع، وفقدان الشبكة.
- ظهور مزودي الخدمة ضمن النطاق المسموح فقط دون كشف إحداثياتهم الدقيقة.
- إنشاء طلب تاكسي وحساب السعر النهائي من الخادم، وقبوله مرة واحدة فقط.
- بدء الرحلة وإنهاؤها وإلغاء الطلب.
- طلب خدمة منزلية ووصوله إلى الفني المؤهل.
- المحادثة والإشعارات والتقييم بعد اكتمال الطلب.
- الاشتراكات وتجديدها وانتهاؤها.

نجاح TypeScript أو Expo Doctor أو تصدير Android لا يعوض اختبار هذه المسارات على أجهزة حقيقية واتصال الإنتاج.

## 7. النشر والمزامنة مع Lovable

المستودع الحالي هو مصدر الشيفرة المعتمد. تُرسل التغييرات إلى `main` عبر Pull Request وفحوصات GitHub. إذا بقي ربط GitHub مع Lovable فعالاً على هذا المستودع، يفترض أن تتزامن التغييرات وفق حالة الربط؛ لا يمكن لـ GitHub Actions وحده إثبات حالة الاتصال أو إجبار Lovable على المزامنة. تحقق من ظهور آخر commit داخل مشروع Lovable بعد الدمج.

## 8. نقاط مؤجلة أو غير مثبتة

- OTP/SMS مؤجل عمداً حسب طلب صاحب المشروع.
- لا يوجد في فحوص CI وحدها إثبات أن AAB موقّع ومتاح للتثبيت.
- لا يوجد إثبات من GitHub أن GPS والخرائط والإشعارات وقاعدة الإنتاج اختُبرت على هاتف حقيقي.
- لا تشارك أي token أو مفتاح خدمة في المحادثة أو داخل ملفات Git.
