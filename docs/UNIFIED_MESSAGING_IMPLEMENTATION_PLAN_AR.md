# خطة توحيد المراسلات في ممنون

> هذه الخطة على الفرع المستقل `feature/unified-whatsapp-chat-20261122` فقط. لا دمج إلى `main` ولا نشر قبل اكتمال مراجعة المستخدم.

## الهدف

استبدال واجهات المراسلة المتفرقة في الويب وAndroid بواجهة موحدة مستوحاة من سهولة الاستخدام وتفاصيل تجربة WhatsApp، مع الاحتفاظ باسم وهوية ممنون. المطلوب توحيد شكل القوائم والمحادثة والكتابة والاختصارات والمقاسات، وليس دمج بيانات أو صلاحيات مختلفة بطريقة قد تكشف محادثة لمستخدم غير مخول.

## جرد أولي من الفرع main

### مراسلات الطلبات والخدمات
- الويب: شاشة تفاصيل الطلب `src/routes/request.$id.tsx` تتعامل مع `chats` و`messages`.
- Android: `expo-app/app/request/chat/[id].tsx` وتستخدم مكوّن `expo-app/components/MamnoonChatThread.tsx`.
- قائمة رسائل Android: `expo-app/app/messages.tsx`.
- قائمة رسائل الويب: `src/routes/messages.tsx`.

### مراسلات الدعم
- الويب: `src/routes/support-chat.tsx` ويستخدم `support_conversations` و`support_messages`.
- Android: `expo-app/app/support-chat.tsx` ويستخدم الجداول نفسها مع صلاحيات الموظفين وإشعارات الدعم.
- توجد أيضاً منظومة تذاكر منفصلة: `src/routes/support.tsx` و`expo-app/app/support.tsx` وتستخدم `support_tickets` و`support_ticket_messages`.

### صندوق الإدارة
- الويب: `src/components/admin-inbox.tsx`.
- Android: `expo-app/app/admin/chats.tsx` ويستخدم `expo-app/components/MamnoonChatThread.tsx`.
- يوجد منطق إدارة ودعم ومساعد ذكي وتحويل للموظف وحالات معالجة؛ يجب الحفاظ عليه.

## مبدأ التنفيذ الآمن

1. توحيد طبقة العرض والتصميم أولاً، مع مكونات منفصلة مناسبة لـ React Web وReact Native، وبنفس قواعد القياس والتباعد والخطوط والأيقونات.
2. إبقاء مصادر البيانات الحالية منفصلة عبر محولات (adapters): محادثة الطلب، محادثة الدعم، وتذكرة الدعم. لا تغيير في مخطط قاعدة البيانات ولا نقل بيانات في المرحلة الأولى.
3. الإبقاء على سياسات RLS والتحقق من المشاركين وصلاحيات الموظفين كما هي. لا استخدام لمفاتيح الخدمة داخل تطبيق العميل.
4. ربط كل شاشة حالية بالمكوّن الموحد تدريجياً، وعدم إزالة أي مسار قديم قبل التحقق من تكافؤ وظائفه.
5. عدم إضافة مرفقات أو صوت أو تحرير/حذف رسائل على أنها تعمل قبل بناء التخزين والصلاحيات والاختبارات اللازمة.
6. اختبار RTL، أحجام الشاشات، لوحة المفاتيح، حالات التحميل والخطأ والاتصال الضعيف، الإرسال والاستلام والقراءة والإشعارات، وحماية الوصول بين المستخدمين.
7. لا تشغيل migrations على قاعدة الإنتاج، ولا إرسال رسائل حقيقية أثناء الاختبارات، ولا تعديل الدفع أو الطلبات أو الصلاحيات خارج نطاق المراسلة.

## مواصفات تجربة الواجهة المطلوبة

- قائمة محادثات موحدة مع البحث والتصفية وغير المقروءة والمفضلة، حيثما تسمح صلاحيات نوع الحساب.
- رأس محادثة بسيط يتضمن صورة/اسم الطرف ومعلومات سياق الطلب عند الحاجة.
- فقاعات رسائل متناسقة، أحجام نص واضحة، توقيت، وفواصل الأيام.
- شريط كتابة صغير ونظيف، وأيقونات اختصار مصغرة لا تزاحم مساحة الرسائل.
- الرد على رسالة، نسخ النص، تحديد/تفاعل، ومشاركة أو تحويل عند دعمها فعلياً.
- حالات الإرسال والفشل وإعادة المحاولة، ومؤشرات القراءة فقط عند وجود دليل موثوق من قاعدة البيانات.
- دعم لوحة المفاتيح والتمرير إلى آخر رسالة دون حجب حقل الكتابة.
- تصميم عربي RTL أولاً، مع الحفاظ على هوية ممنون وعدم استخدام شعار WhatsApp أو علامته.

## ما تم حتى الآن

- فحص المستودع والفرع الافتراضي وملفات المراسلة الأساسية.
- إنشاء هذا الفرع من أحدث `main`.
- لم يتم تعديل قاعدة البيانات أو تنفيذ أي إرسال أو نشر.
- هذه الخطة جرد أولي؛ سيتم تحديثها مع كل كود أو مطلب إضافي يرسله المستخدم قبل اعتماد التنفيذ النهائي.
