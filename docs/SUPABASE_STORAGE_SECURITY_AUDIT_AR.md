# تدقيق Supabase Storage — ممنون

المشروع: `enteiolvirenbhkyskgb`
الفحص: قراءة إعدادات buckets وسياسات `storage.objects` فقط.

## المخازن الموجودة

| Bucket | عام؟ | الحد الأعلى | أنواع الملفات |
|---|---:|---:|---|
| `avatars` | نعم | 5 MB | JPEG / PNG / WebP |
| `provider-verification` | لا | 10 MB | JPEG / PNG / WebP |
| `regional-notices` | نعم | 5 MB | JPEG / PNG / WebP |
| `request-attachments` | لا | 8 MB | JPEG / PNG / WebP |

## السياسات التي رُصدت

- الصور الرمزية: القراءة عامة، والرفع/التحديث/الحذف محصور بمجلد المستخدم الذي يطابق `auth.uid()`.
- ملفات التحقق: القراءة للمالك أو الموظف الذي يملك دوراً إدارياً، والرفع/التحديث محصور بمجلد المستخدم.
- مرفقات الطلب: الرفع والحذف للمستخدم صاحب الطلب، والقراءة للمشارك في الطلب (الزبون أو مقدم الخدمة أو صاحب العرض) أو من لديه صلاحية عمليات مقدمي الخدمة.
- صور الإعلانات/الإشعارات الإقليمية: القراءة عامة، والرفع يتطلب مجلد المستخدم المطابق لـ`auth.uid()` مع `has_admin_access(auth.uid())`.

## ملاحظات أمنية

1. كون `avatars` و`regional-notices` عامّين يعني أن أي شخص لديه رابط الملف يستطيع قراءته؛ هذا مقصود للصور العامة فقط. يجب عدم رفع مستندات شخصية أو إثباتات تحقق إلى هذين المخزنين.
2. `provider-verification` و`request-attachments` خاصّان، وهذا مناسب لطبيعة محتواهما. يجب أن تستمر الواجهات باستخدام signed URLs أو جلسة المستخدم وعدم تحويلهما إلى public.
3. حد MIME محصور في JPEG/PNG/WebP، وهو جيد كبداية لكنه لا يغني عن التحقق من محتوى الملف فعلياً (file signature) والحجم والأبعاد ومكافحة إساءة الاستخدام.
4. مسارات الملفات جزء من نموذج الصلاحيات: لا تغيّر ترتيب المجلدات أو أسماءها دون تحديث السياسات والعميل واختبار الرفع والقراءة والحذف.
5. لم يتم إجراء أي تعديل على buckets أو السياسات أو الملفات.

## اختبارات مطلوبة قبل إعلان اكتمال النقل

- مستخدم A لا يستطيع قراءة أو حذف إثباتات المستخدم B.
- الزبون لا يقرأ مرفقات طلب لا يملكه ولا يشارك فيه.
- مقدم الخدمة لا يقرأ مرفقات طلب لم يُعرض عليه أو لم يُقبل فيه.
- الموظف يرى ملفات التحقق فقط ضمن صلاحيات دوره ونطاقه.
- مستخدم عادي لا يرفع صورة إشعار إقليمي.
- الرفع يرفض امتداداً أو MIME غير مسموح وحجماً أكبر من الحد.
- التطبيقان Web وAndroid يعيدان استخدام نفس مسارات التخزين ونفس قواعد الملكية.

## النتيجة

هناك أساس Storage موجود ومقسّم حسب الحساسية، ولا حاجة إلى نقل الملفات إلى خدمة أخرى. المطلوب هو توحيد استخدام الويب والأندرويد لهذه المخازن واختبار سياسات الوصول، مع إبقاء إثباتات التحقق ومرفقات الطلبات خاصة.
