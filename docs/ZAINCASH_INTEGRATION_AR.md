# تجهيز بوابة زين كاش — ممنون

## الحالة الحالية
- واجهة اشتراكات الويب لا تستدعي QiCard؛ تعرض أن زين كاش قيد الإعداد ولا تخصم أي مبلغ.
- إعداد `subscription_settings.payment_gateway_enabled` يبقى `false` إلى أن يكتمل الربط والاختبار.
- لا توجد حالياً Edge Function منشورة خاصة بإنشاء دفعات زين كاش أو استقبال Webhook.
- تطبيق Android لا يملك حالياً مسار دفع اشتراك فعّالاً.
- طلبات الرحلات والخدمات تُنشأ حالياً دون بدء دفع إلكتروني. القيمة الافتراضية الحالية لطريقة الدفع في قاعدة البيانات هي `cash`.
- جدول `driver_wallets` هو سجل أرباح السائق وعمولاته، وليس رصيداً نقدياً قابلاً للشحن أو محفظة دفع للزبون.
- توجد دالة قاعدة بيانات قديمة باسم `finalize_qicard_subscription_payment`، وصلاحية تنفيذها محصورة بـ `service_role` و`postgres`. لا تستخدمها واجهة العميل. يجب استبدالها بمسار موحد خاص بزين كاش بعد مراجعة ترحيل قاعدة البيانات، لا حذفها عشوائياً.

## متطلبات الربط التي ستُستكمل بعد استلام بيانات التاجر
تُضاف القيم كـ Supabase Edge Function Secrets فقط، ولا تُحفظ في GitHub أو متغيرات الواجهة:
- `ZAINCASH_CLIENT_ID`
- `ZAINCASH_CLIENT_SECRET`
- `ZAINCASH_API_KEY`
- `ZAINCASH_BASE_URL` (UAT أولاً، ثم عنوان الإنتاج المعتمد من زين كاش)

## تدفق الدفع المطلوب
1. يتحقق الخادم من جلسة المستخدم وصلاحيته.
2. يحسب الخادم السعر من خطة الاشتراك أو الطلب المخزن، ولا يثق بمبلغ مرسل من التطبيق.
3. ينشئ سجل محاولة دفع بحالة `pending` ومرجع UUID فريد، والعملة `IQD`.
4. يطلب الخادم رمز OAuth من زين كاش ثم ينشئ المعاملة ويعيد رابط التحويل الرسمي كما ورد من البوابة.
5. بعد عودة المستخدم، لا تُعد صفحة النجاح دليلاً على الدفع.
6. يتحقق الخادم من JWT الموقّع بخوارزمية HS256 ومفتاح API، ويتحقق كذلك من رقم المعاملة والمرجع والمبلغ والعملة.
7. يستخدم الخادم Inquiry API عند الحاجة، ويعالج Webhook مع منع التكرار باستخدام `eventId`.
8. فقط بعد تأكيد `SUCCESS` موثّق، يفعّل الاشتراك أو يسجل تسوية الطلب. حالات `PENDING` و`FAILED` و`EXPIRED` وعمليات الاسترداد لا تمنح اشتراكاً ولا تُسجل كدفعات ناجحة.
9. كل تحديث مالي يجب أن يكون ذرياً وقابلاً لإعادة المحاولة دون تكرار (idempotent).

## نطاقات الدفع
- اشتراكات البرونزي والفضي والذهبي: زين كاش فقط للدفع الإلكتروني.
- الرحلات وطلبات الخدمات: زين كاش فقط للدفع الإلكتروني، مع بقاء النقدي خياراً مستقلاً.
- المنح الإدارية والاشتراك المجاني البرونزي لا تمر عبر بوابة الدفع ولا يجوز أن تُستبدل بمنحة مدفوعة.
- لا يجوز تغيير اشتراك ممنوح من الشركة من حساب صاحبه.

## قائمة التحقق قبل التفعيل
- [ ] الحصول على موافقة حساب التاجر وبيانات UAT.
- [ ] تنفيذ Edge Functions لإنشاء الدفع والتحقق وWebhook/Inquiry.
- [ ] إنشاء سجل دفع موحد للرحلات والخدمات مع ربطه بالطلب والمبلغ.
- [ ] ترحيل دالة الاشتراكات القديمة من QiCard إلى تأكيد زين كاش الموثق.
- [ ] تطبيق واجهة الدفع على الويب وAndroid مع عرض حالات الانتظار والفشل والنجاح.
- [ ] اختبار مبالغ صحيحة وخاطئة، عملة خاطئة، توقيع JWT خاطئ، تكرار Webhook، إلغاء، انتهاء صلاحية، وإعادة المحاولة.
- [ ] تشغيل اختبارات UAT كاملة ومراجعة سجلات الخادم.
- [ ] تفعيل إعداد الدفع بعد اجتياز الاختبارات وموافقة صاحب المشروع.
- [ ] تسجيل Webhook الإنتاج مع زين كاش، ثم اختبار معاملة إنتاجية منخفضة القيمة.
